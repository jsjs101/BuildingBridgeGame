# TRUSS LAB · Google Apps Script 랭킹 연결

게임 파일은 BridgeV8에 적용되어 있습니다. Google 계정에서 아래 배포를 한 번 완료하면 됩니다. Gemini Worker와는 별도로 동작하며 API 키는 필요하지 않습니다.

## 기존 배포를 여러 기록 등록 방식으로 업데이트하기

1. Apps Script 편집기의 Code.gs를 이 폴더의 최신 Code.gs 전체 내용으로 교체하고 저장합니다.
2. 위쪽 함수 선택 메뉴에서 `setupRanking`을 고르고 **▶ 실행**을 누릅니다. 기존 기록을 삭제하지 않고 마지막 I열에 `attemptId` 제목을 추가합니다. 기존 열을 직접 이동하거나 지우지 마세요.
3. **배포 → 배포 관리 → 기존 웹 앱의 수정(연필) → 버전: 새 버전 → 배포**를 선택합니다. 기존 배포를 수정하면 게임에 입력한 URL은 그대로 사용합니다.
4. 게임을 새로고침합니다. 이전에 등록한 기록은 유지되며, 이후 새 클리어부터 별도 행으로 등록됩니다.

## 1. 랭킹용 스프레드시트 만들기

1. Google Sheets에서 빈 스프레드시트를 만듭니다. 이름은 `TRUSS LAB 랭킹` 등으로 정합니다.
2. 메뉴의 **확장 프로그램 → Apps Script**를 엽니다.
3. 편집기의 `Code.gs` 내용을 지우고 이 폴더의 **Code.gs 전체 내용**을 붙여 넣습니다.
4. 저장한 뒤 상단 함수 선택 목록에서 **setupRanking**을 선택하고 **실행**을 누릅니다.
5. 본인의 스프레드시트에 접근할 권한을 승인합니다. 본인이 붙여 넣은 코드와 계정인지 확인하세요.
6. 시트에 `Rankings` 탭과 열 제목이 생성되었는지 확인합니다. 열 제목과 순서는 바꾸지 마세요.

시트 자체를 인터넷에 공개하거나 링크 공유할 필요는 없습니다. 브라우저 식별용 해시도 있으므로 시트는 관리자만 보관하세요.

## 2. 웹 앱으로 배포하기

1. Apps Script 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형을 **웹 앱**으로 선택합니다.
3. **다음 사용자 인증 정보로 실행: 나**를 선택합니다.
4. **액세스 권한이 있는 사용자: 모든 사용자**를 선택합니다. 로그인하지 않은 사용자도 접근할 수 있어야 합니다.
5. **배포**를 누르고 `/exec`로 끝나는 웹 앱 URL을 복사합니다. `/dev` 주소나 편집기 주소를 복사하지 마세요.

학교·회사 계정에서 ‘모든 사용자’를 선택할 수 없다면 조직의 외부 공개 정책을 확인해야 합니다. 로그인 전용 배포는 이 익명 랭킹 연결에 사용할 수 없습니다.

## 3. 게임에 주소 입력하기

BridgeV8의 `project-settings.json`에서 다음 부분에 복사한 URL을 넣습니다.

```json
"ranking": {
  "enabled": true,
  "webAppUrl": "https://script.google.com/macros/s/배포_ID/exec",
  "season": "v8-1"
}
```

주소 양쪽의 큰따옴표를 유지합니다. `season`은 Code.gs의 `RANKING_SEASON`과 같아야 합니다. 예시의 `배포_ID` 대신 실제 배포 주소 전체를 붙여 넣으세요.

저장 후 `http://127.0.0.1:5500/BridgeV8/index.html`을 새로고침합니다. 배포 주소는 공개되어도 되는 연결 주소이며 비밀번호나 API 키를 넣으면 안 됩니다.

## 4. 동작 확인

1. 개발자 모드가 꺼진 상태에서 캠페인 계약 하나를 정상 완료합니다.
2. 완료 모달 오른쪽에 이번 설계 비용과 랭킹 패널이 표시됩니다.
3. 닉네임을 입력하고 **기록 등록**을 누릅니다.
4. 시트의 `Rankings` 탭에 한 행이 추가되고, 게임에 순위가 나타나는지 확인합니다.
5. 다른 브라우저 또는 다른 컴퓨터에서 같은 계약·같은 난이도를 완료해 등록합니다. 기록이 두 개로 보이는지 확인합니다.
6. 같은 브라우저에서 계약을 다시 완료해 등록하면 새 행이 추가됩니다. 비용이 같거나 더 높아도 별도 기록으로 남습니다. 같은 클리어의 재전송은 중복 저장하지 않습니다. 등록 간격은 최소 10초입니다. 순위는 비용만으로 계산합니다.

첫 접속에서는 서버를 시작하느라 응답이 늦을 수 있습니다. 연결 실패 시 **새로고침**으로 다시 조회합니다. 요청 시간이 초과되어 종료되었다면 결과창을 닫고 다시 여세요. `no-cors`로 변경하면 응답을 읽을 수 없으므로 사용하지 않습니다.

## 표시 기준

- 계약 48개와 쉬움/어려움 난이도를 각각 분리합니다. 샌드박스·튜토리얼·실패 기록은 등록하지 않습니다.
- 상위 비율은 `순위 ÷ 비교 기록 수 × 100`입니다. 같은 비용은 공동 순위입니다. 기록 1개 중 1위는 상위 100%, 100개 중 1위는 상위 1%로 표시합니다. 숫자 왼쪽의 세로 막대는 `100 − 상위 비율`만큼 채워져 상위에 가까울수록 높습니다.
- 등록 전에는 기존 기록에 이번 설계 1건을 더한 **예상 순위**입니다. 기존 내 기록의 로그인 조회가 아니므로 재접속 시 이미 등록한 내 기록도 비교 대상에 포함될 수 있습니다.
- 등록 후에는 **이번에 등록한 기록**의 순위를 표시합니다. 브라우저별 기록 수 제한은 없으며, 새로운 클리어마다 별도로 등록할 수 있습니다. 같은 클리어의 등록 버튼은 성공 후 비활성화됩니다.
- 순위 목록에는 상위 기록 8개와, 해당 범위 밖에 있는 이번 기록을 보여줍니다. 화면에는 순위·닉네임·비용과 상위 비율 막대만 표시하며 설계 도면과 비용 분포 그래프는 표시하지 않습니다.
- 기록 등록을 눌렀을 때 닉네임·설계 좌표와 연결·재료·비용·시간·최대 이용률을 전송합니다. 도면은 정적 미리보기이며 주행 영상이나 재생 기록은 아닙니다.
- 브라우저에 익명 식별용 임의 토큰을 저장합니다. 서버에는 토큰의 해시만 저장하고 공개 응답에서는 제외합니다. 브라우저 저장소 삭제·기기 변경 시 다른 플레이어로 간주됩니다. 계정 로그인 및 다중 기기 연동은 없습니다.
- 개발자 로그인이나 개발용 설정 변경이 있는 실행은 조회만 허용합니다. 게임 규칙이나 재료 가격을 바꾸면 시즌도 변경하여 기존 기록과 섞이지 않게 하세요.

## 운영과 한계

이 구현은 **커뮤니티 랭킹**입니다. 서버는 입력 크기·재료·연결 관계·닉네임을 검사하고 좌표로 비용을 재계산합니다. 성공 판정·물리 시뮬레이션은 서버에서 재실행하지 않으므로 변조된 클라이언트나 여러 익명 토큰을 통한 부정 등록을 완전히 막지는 못합니다. 공식 경쟁 서비스에는 서버 측 주행 검증과 사용자 인증이 추가로 필요합니다.

한 기록은 연결점 300개, 부재 500개, 설계 JSON 40,000자까지 허용합니다. 등록은 같은 토큰당 10초 간격이며, 쓰기는 Script Lock으로 직렬화합니다. 시트 전체에 기록 5,000개가 쌓이면 신규 등록을 중단합니다. 이미 저장한 기록의 재전송 확인과 조회는 가능합니다. 규모가 커지면 시즌별 시트 보관 또는 별도 데이터베이스로 옮기세요. Google Apps Script의 일일 실행·서비스 한도도 적용됩니다.

모든 사용자에게 열린 웹 앱이므로 주소를 아는 사람은 제출을 시도할 수 있습니다. 게임에 숨길 수 있는 서버 비밀 키를 넣는 방식으로 보호하지 않습니다. 필요하면 관리자가 의심스러운 행을 시트에서 삭제할 수 있습니다.

서버 코드를 수정한 뒤에는 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 갱신합니다. 시즌을 변경할 때 게임 JSON과 `RANKING_SEASON`을 함께 바꾸세요. 이전 기록은 시트에 남지만 새 시즌 조회에서 제외됩니다. `setupRanking`을 다시 실행해도 기존 행을 지우지 않습니다.

## 오류 확인

- `랭킹 서버 연결 준비 중`: 게임 JSON의 `webAppUrl`이 비어 있습니다.
- Google 로그인 화면 또는 HTML 응답: 배포가 웹 앱인지, 접근 권한이 모든 사용자인지, `/exec` 주소인지 확인합니다.
- `시즌이 다릅니다`: JSON의 season과 서버 RANKING_SEASON을 일치시킵니다.
- `설계 비용이 일치하지 않습니다`: 기본 재료 가격과 원본 설계로 다시 실행합니다. 가격을 변경했다면 서버의 RANKING_COSTS도 맞추고 새 시즌으로 분리하세요.
- `setupRanking을 먼저 실행`: 편집기에서 setupRanking을 직접 실행합니다. doGet/doPost는 편집기의 실행 버튼으로 테스트하지 않습니다.
- 요청 실패 상세 내용은 Apps Script의 **실행** 목록과 브라우저 개발자 도구의 **콘솔**에서 확인합니다.

## 코드 검증

프로젝트 폴더에서 다음 명령으로 서버 로직의 자동 검증을 실행합니다.

```powershell
node --test BridgeV8/apps-script-ranking/ranking.test.cjs
```

실제 Google 배포·권한·브라우저 간 통신은 위 ‘동작 확인’ 절차로 별도 확인해야 합니다.

Google 공식 문서: [웹 앱 배포](https://developers.google.com/apps-script/guides/web), [JSON 응답과 리다이렉트](https://developers.google.com/apps-script/guides/content), [동시 쓰기 잠금](https://developers.google.com/apps-script/reference/lock/), [서비스 한도](https://developers.google.com/apps-script/guides/services/quotas).
