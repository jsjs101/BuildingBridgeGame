# AI 체험 부스용 TRUSS LAB

시연 페이지는 `BridgeV9/bridge.html`입니다. 본편은 기존 `index.html`에서 그대로 실행합니다.

시연은 마우스와 키보드가 있는 PC에서 진행하세요. VS Code Live Server를 사용 중이라면 다음 주소로 접속하세요.

http://127.0.0.1:5500/BridgeV9/bridge.html

## 진행 순서

난이도를 선택하거나 **체험 시작**을 누르면 전체 화면 현장 지도가 열립니다. 지도에서 **연습 시작**으로 첫 단계를 시작하고, 화살표로 다른 단계를 둘러볼 수 있습니다. 시간 제한이나 자동 종료는 없습니다. 설계 경과 시간은 기록·랭킹에 사용합니다.

1. **첫 다리 연습** — 도로와 목재 연결, 차량 시험, AI 질문을 기존 튜토리얼로 배웁니다.
2. **더 긴 다리** — 튜토리얼보다 긴 다리를 목재 삼각형으로 보강합니다.
3. **비와 눈 속 오르막** — 강화 도로와 강철을 사용합니다. 도로 길이당 7 N/u의 기상 하중을 차량 하중에 더해 계산합니다.
4. **배와 화물차의 교차** — 약 1.5배 커진 선박 위로 아치형 도로를 만들고 화물차도 통과시킵니다. 양쪽 교대는 아치의 수평 반력을 받는 핀 지지로 구성했습니다.

5. **아래에서 당기는 케이블** — 강화 도로 가운데에서 아래로 강철 기둥을 내리고, 아래 끝을 양쪽 지지점에 케이블로 연결합니다. 첫 진입 시 구조 코치가 제작 순서와 인장·압축을 안내합니다.

튜토리얼 이후 2~5단계에는 자재가 설치되어 있지 않습니다. 지지점과 도로 경로 안내를 참고해 도로와 골조를 처음부터 직접 만듭니다. 4단계는 중앙이 높은 도로 경로와 큰 항로를 제공합니다. 이동·삭제 도구도 그대로 사용할 수 있습니다. **AI에게 질문**을 누르면 현재 다리에 맞는 질문이 입력되며, 전송은 사용자가 직접 합니다.

본편과 같은 간소화된 2D 구조·붕괴 물리를 사용합니다. 비·눈의 추가 하중은 교육용 시나리오이며 실제 교량 설계 기준을 재현하는 수치는 아닙니다. 쉬움·어려움 난이도에 따라 예산·차량 하중·허용 변형이 달라집니다.

## 설계 이어하기와 다음 체험자

- **단계 안내**에서 잠시 나갔다가 설계를 계속할 수 있습니다. 새로고침해도 같은 탭의 단계와 설계를 이어 갑니다. 튜토리얼 도중 새로고침하면 튜토리얼을 처음부터 진행합니다.
- 열린 단계는 현장 지도에서 다시 선택할 수 있습니다. 완료한 단계에서 **다시 도전**을 누르면 새 설계로 시작하고, 기존 완료 기록은 유지합니다.
- 시간이 부족하면 **다음 단계 둘러보기**를 사용할 수 있습니다. 건너뛴 단계는 완료로 기록하지 않습니다.
- **다음 체험자 · 초기화** 또는 마지막 화면의 **다음 체험자 · 새로 시작**을 누르면 시연 기록과 AI 대화를 비우고 처음으로 돌아갑니다.
- 시연 기록과 환경 설정은 `trusslab-booth:` 이름의 탭별 sessionStorage에 저장합니다. 본편 localStorage 진행도는 변경하지 않습니다. 브라우저 탭을 닫으면 시연 기록이 사라집니다.

## AI 및 운영 준비

AI는 기존 `project-settings.json`의 `geminiWorkerUrl`과 Worker를 공유합니다. 같은 서버에서 `index.html` 대신 `bridge.html`을 열면 서버 주소를 다시 입력할 필요가 없습니다. 새로운 도메인·포트에서 시연한다면 Worker의 `ALLOWED_ORIGINS`에 해당 출처를 등록해야 합니다. API 키는 웹페이지에 넣지 않습니다.

시연판은 본편 세트 선택, 개발자 모드와 샌드박스를 사용하지 않습니다. 2~5단계 완료창에서 닉네임을 입력하고 **랭킹 등록**을 누르면 별도 랭킹 페이지에서 비용 순위·상위 비율·건설 시간을 확인할 수 있습니다. 본편 기록과는 별도의 `booth_v2_long`, `booth_v2_weather`, `booth_v2_harbor` 순위표를 사용하며 쉬움·어려움도 분리합니다.

**랭킹을 사용하려면 서버도 갱신해야 합니다.** 기존 Apps Script의 `Code.gs`를 `apps-script-ranking/Code.gs` 내용으로 교체하고 저장한 뒤, **배포 → 배포 관리 → 기존 배포 수정(연필) → 버전: 새 버전 → 배포**를 선택하세요. 기존 URL과 시즌 `v8-2`를 유지하며 본편 기록은 삭제하지 않습니다. 시트 열은 바뀌지 않으므로 이미 설정을 마쳤다면 `setupRanking`을 다시 실행할 필요는 없습니다. 이전 서버는 시연 계약을 거절합니다.

방문자가 직접 닉네임을 입력하고 **기록 등록**을 눌렀을 때만 공개됩니다. 다음 체험자 초기화는 이 탭의 닉네임과 식별값도 비우지만 이미 서버에 공개한 기록은 삭제하지 않습니다. 시연 전에 실제 행사 네트워크에서 AI 질문 전송을 한 번 확인하고 다음 체험자 초기화를 눌러 주세요.

## 파일 구성

- `bridge.html`: 본편과 같은 화면 구조를 사용하는 별도 진입점
- `bridge.js`: 네 단계의 미션 데이터, 5단계 진행과 초기화
- `bridge.css`: 시연 진행 표시와 단계 안내 화면
- `script.js`, `style.css`, `environment.js`: 본편과 공유하는 게임·디자인·배경

미션 이름·형상·기본 예산·하중·사용 가능한 재료는 `bridge.js` 상단의 `missions`에서 조정할 수 있습니다. 다리 길이나 하중을 바꾸면 실제 차량 시험으로 통과 가능 여부를 다시 확인하세요.

이전 시간 제한·기본 골조가 포함된 설계와 섞이지 않도록 이번 변경 이후 첫 접속은 새 시연 세션으로 시작합니다. 본편 진행도에는 영향을 주지 않습니다.

## 구조 안정성 판정

도로 이음부는 하나의 완전한 용접 거더보다 유연하게 계산합니다. 압축력이 커지면 기존 탄성 강성에 기하 강성을 더한 접선 강성을 검사하여 경간 전체의 좌굴을 판정합니다. 도로에 연결점을 더 찍는 것만으로 중간 지지나 트러스가 생기는 것은 아닙니다. 실제로 연결한 보강재의 강성이 계산에 참여합니다.

좌굴·파단 뒤에는 기존 붕괴 물리로 이어집니다. 도로가 크게 처져 차량이 걸리는 경우에는 통과 처리하지 않고 정체와 다시하기 안내를 유지합니다. 파단 끄기는 차량 통과를 보장하는 기능이 아닙니다.

기본 수치 검사는 프로젝트 상위 폴더에서 `node --test BridgeV9/physics.test.cjs`로 실행할 수 있습니다. 실제 플레이는 별도로 다리를 건설해 시험해야 합니다.

눈·비를 움직이려면 인게임 **도구 → UI·그래픽 설정 → 동작 줄이기 → 끄기**를 선택하세요. 날씨는 이 게임 설정을 따르며, 운영체제의 동작 줄이기가 켜져 있어도 게임에서 끄면 움직입니다. 켜기를 선택하면 정적으로 표시합니다.

새 5단계의 랭킹 ID는 booth_v2_cable입니다. 기존 Apps Script 배포의 Code.gs를 최신 파일로 교체하고 새 버전으로 배포하면 새 단계 기록을 등록할 수 있습니다. 기존 시즌과 기록은 이어서 사용합니다.

5단계 자재 한도는 강화 도로 6개와 강철 1개입니다. 케이블은 개수 제한이 없으며, 안내 표시와 시험 시작·랭킹 서버에서 한도를 검사합니다.

## 체험 엔딩과 크레딧

마지막 단계를 통과한 뒤 **체험 마치기**를 누르면, 각 단계에서 완성한 실제 설계를 입체로 재구성한 엔딩이 재생됩니다. 다섯 장소를 차례로 돌아본 뒤 전체 파노라마와 크레딧으로 이어집니다. 기본 연출은 약 44초이며, 크레딧은 천천히 자동으로 올라갑니다. 일시 정지, 크레딧 바로 보기, 단계 지도 복귀와 엔딩 다시 보기를 지원합니다. Escape를 한 번 누르면 크레딧, 다시 누르면 지도로 돌아갑니다.

- `booth-ending.js`: 실제 설계의 도로·양쪽 골조·케이블을 폴리곤으로 구성하고, 카메라·안개·환경·차량과 엔딩 시간을 관리합니다. 기존 디오라마의 모델링 함수와 날씨 함수를 재사용합니다.
- `booth-ending.css`: 자막·진행 표시·크레딧 화면입니다.
- `credits.json`: 크레딧 제목, 감사 문구, 역할별 이름, 단계별 이야기와 연출 시간을 편집합니다. `sections`에 `{ "title": "역할", "names": ["이름"] }`을 추가할 수 있습니다. 수정 후 새로고침하면 반영됩니다. 이름은 일반 텍스트로 표시합니다.

완성한 설계는 기존 체험 세션 안의 `designs`에 보관합니다. 새 체험자 초기화 시 함께 지워지며, 본편 저장 데이터에는 영향을 주지 않습니다. 이전 세션의 완료된 단계는 저장된 설계 초안이 있으면 복원합니다. 설계가 남아 있지 않은 단계는 '저장된 설계 없음'으로 표시합니다. 예시 다리를 사용자의 작품처럼 표시하지 않습니다.

멀리 보이는 지역의 나무·난간은 단순화하고 화면 밖 면은 제외합니다. 화면 해상도 배율은 최대 1.5이며, 크레딧 배경이 정착하면 3D 장면의 재렌더링을 중단합니다. 탭을 숨기면 프레임을 중지하고, 엔딩 종료 시 입력·관찰자·프레임을 해제합니다. 동작 줄이기 사용 시 카메라를 완만한 원거리 이동으로 바꿉니다. 엔딩 안의 카메라 고정 버튼으로 현재 구도를 멈추거나 연출을 다시 켤 수 있습니다.

엔딩의 44초 안에서 우편차 출발, 통학버스, 겨울 물자 운송, 선박과 교차, 꾸러미 전달을 보여줍니다. 인물의 손 인사와 걸음, 회전하는 차량 바퀴, 움직이는 배와 항적을 포함합니다. 카메라는 시간 간격을 반영한 Hermite 경로로 접근·측면 이동·항구 저공 촬영·전체 풍경을 연속적으로 연결합니다. 각 단계 7초와 파노라마 9초는 그대로입니다. 외부 모델이나 새 렌더링 라이브러리를 추가하지 않습니다.

엔딩은 브라우저의 WebGL 깊이 버퍼로 면의 앞뒤를 판정해 인물·선박이 지형이나 물에 잘못 가려지는 문제를 방지합니다. 기존 모델의 폴리곤 데이터를 재사용하며 외부 렌더링 라이브러리를 요구하지 않습니다. WebGL을 지원하지 않으면 기존 Canvas 렌더링으로 재생합니다. 종료 시 GPU 버퍼와 프로그램, 컨텍스트를 해제합니다.

엔딩의 다섯 지역은 하나의 계곡으로 이어집니다. 연결 구간은 양쪽 도로의 높이와 폭, 강둑의 꼭짓점을 공유합니다. 지역에 따라 숲과 설원이 바뀌고, 전경으로 이어지는 강들은 호수에 합류합니다. 새 지형은 엔딩 화면에만 사용되며 설계와 플레이 데이터는 기존과 같습니다.
